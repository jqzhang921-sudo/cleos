# 0.41.70：补齐聊天里的朋友圈发布与互动

版本：0.41.70（147）。检查日期：2026-10-09。

## 问题与改动

0.41.69 只给普通聊天提供了 `read_feed`，没有发布、点赞与评论工具。虽然朋友圈页面和后台已有发布互动能力，模型在聊天里仍只能读取；用户说「去发个朋友圈」时，模型无法实际发布。

- 新增 `publish_feed`：直接写入 App 内的文字日常动态，正文 1–1200 字，不再让用户自己复制粘贴。不附图，不自动查询或编造资讯来源。
- 新增 `like_feed`：明确设置点赞或取消赞，重复调用不会反复切换；只改当前 TA 的赞，保留用户和其他 TA 的状态。
- 新增 `comment_feed`：评论动态或回复具体朋友，正文 1–200 字，保留回复关系；自己的帖子只能回复朋友评论，不能赞自己或回复自己的评论。
- 作者由程序绑定到实际调用工具的 TA，工具参数不能指定用户或其他 TA 作为作者。检查角色和帖子是否存在，在 Room 事务中读取最新状态并更新，保留照片、来源和已有互动。
- 防止重复发布最近相同正文或重复留言；工具只有写入成功后才返回完成信息，存储失败不报告成功。
- 聊天请求实际提供读、发、赞、评论四种工具。提示词明确读取工具的只读性质不限制其他操作，以本次工具列表为准，不沿用旧聊天的能力判断。
- 「设置 › 能做的事 › 发朋友圈与互动」默认开启，可与「看朋友圈」分别关闭。点赞和留言前需确认具体帖子；普通后台聊天唤醒不获得读写工具，后台主动阅读与自动发帖开关保持独立。
- 同一份 App 内朋友圈由所有 TA 共用；不操作微信或其他 App。数据库结构保持 31，不新增依赖，不加入 OCR。
