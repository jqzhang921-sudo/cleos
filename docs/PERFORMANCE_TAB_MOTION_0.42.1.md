# Cleos 0.42.1 · 悬浮导航优化候选

状态：本地测试包，未公开发布，也未在反馈问题的两款手机上验收。

## 反馈范围

- Redmi Note 13 Pro / HyperOS 3.0.306.0：悬浮导航卡顿。
- Samsung S25 / One UI 8.5：整体卡顿，具体瓶颈尚未定位。

以上为用户转述，不能据此归因于某个品牌的性能或驱动。

## 修改

原拖动路径在每个触摸事件中启动动画任务，松手时存在两个回弹控制点。现在每次手势只保留一个随显示帧更新的跟随任务，触摸事件只替换最新目标；停稳后等待下一次目标，不持续绘制。松手只提交最终页面，由一个位置动画负责回弹。同一页内松手也会归位。

按压材质的状态读取收在独立的镜片组合范围内，减少整条导航随动画重复组合。高速拖动的变形有上限；取消手势不提交新页面，并兼容系统关闭动画。保持现有玻璃材质、纯图标布局和辅助功能名称。

没有修改全局玻璃渲染质量，没有按品牌降低视觉效果，没有修改数据结构、权限或联网行为。

## 验证及限制

- 最终生产源码：1516 项 JVM 测试通过，正式签名构建通过。
- 独立 Android 模拟器：四入口点按、双向拖动、同页松手、快速点按、同指反向拖动、退后台取消再恢复、系统关闭动画均通过。停稳后的两秒采样为 0 个新增渲染帧。
- 测试库 45 张表 / 133 行、设置、图片、阅读锚点和序列均恢复一致；独立模拟器已关闭。未操作用户手机。
- 同机同场景、预热后的 8 次拖动对比：0.42.0 帧耗时 P50/P90/P95/P99 为 36/48/57/77ms；候选版为 36/48/57/73ms。报告的卡顿帧占比约 9.2% → 8.8%。这是接近持平的一轮模拟器结果，不能证明真实设备提速，也不能证明三星整体卡顿已解决。

下一步需要反馈设备上的实际对比。若红米导航仍卡，应进一步采集拖动时的帧时间；三星需定位聊天滚动、输入、切页或静置等具体场景，再决定后续修改。
