# Goal：记录页月历与列表的连续切换

创建：2026-11-05。用户明确要求参考桌面 switch 文件夹的图片，判断可行后直接建立 Goal。

## 目标与参考

在日记、待办的月历与列表之间实现自然、可逆的切换过渡，延续 Cleos 的玻璃材质和现有导航结构，完成真实可用的流程及实机验证。

截图是剪辑器里 0.1x 慢放视频的取帧，只能用于分析形态，不能从截图推断真实帧率、精确时长或手势方式。可明确借鉴的是：月历与列表在相近空间内渐隐／显现，前后有连续关系，固定导航不随整个页面闪动。不照搬参考中的白色底板、文字或业务布局。

## 当前实现与待处理问题

- RecordsTab 共享日期和持久视图模式，日记、待办各自保存筛选、滚动和输入状态。
- RecordsCalendar 提供月历及收为周历的现有能力；模式按钮位于右上角。
- DiaryListScreen、TodoScreen 主要通过条件分支直接增删月历／日期条，缺少统一的模式过渡。
- 两处 viewportKey 都包含视图模式及月／周折叠状态，变化时会立即滚动回顶，可能与新过渡冲突。

## 实施顺序

1. 建立共用切换状态与动效规范。点击右上角模式按钮后，内容区以短促的淡出／显现和必要的小幅位置过渡完成衔接；起始约 260–340ms，依据实机调节。不增加大幅横移、翻转、3D 或整页白闪。
2. 接入日记与待办，协调月历空间、日期条和列表布局变化，保留顶栏、日记／待办切页、筛选和底部导航的稳定性。月／周折叠与视图切换应协调，但不新增新的手势系统。
3. 处理状态连续性：选中日期、浏览月份、全部／未安排范围、作者筛选、日记／待办各自的列表位置及未发送待办草稿。区分真正的筛选变化与单纯换视图，避免仅换视图就突然回顶；明确原有模式默认选日逻辑，避免动画期间偷偷改变过滤结果。
4. 支持快速往返、中途反向和离页恢复；只让当前有效层接受点击与滚动，不让退出画面继续响应、不重复触发编辑／完成／新增操作。遵循系统关闭动画的设置。
5. 验证玻璃背景采样与过渡，避免叠两份完整玻璃页面造成重复折射、拖影或文字长时间重叠；按现有组件选择最小必要的过渡层。不能仅凭截图宣称零掉帧。

## 验收

- 日记与待办均完成月历→列表→月历；月历、周历、全部日期、选定日期、未安排、筛选及空状态没有错位。
- 长列表保持有意义的滚动锚点；日记／待办切换、旋转、返回恢复不丢筛选或草稿。
- 连续点按／中途反向后，最终视图与按钮一致，无空白页、双重点击层或卡住的动画。
- 待办完成、编辑、新增和日记打开、编辑行为回归；不修改数据结构、记录内容、提醒或主动消息调度，不请求模型。
- 使用自有合成资料进行状态与原生交互验证，适当覆盖小屏、较大字体、横屏及系统动画关闭；测试应针对状态保持和交互风险，不为纯样式写镜像测试。
- 构建正式原签名包并核对身份；按现有授权在手机连接且没有编辑／计时／通话等活动时保留数据更新，并检查实际切换。未完成的实机或性能验证如实记录，不以构建通过替代。

## 边界与完成标准

本 Goal 聚焦记录页的视图过渡，不扩展到整个 App 动效改造、专注新阶段或主动消息修正；之前排定的专注收尾→主动消息优化→考虑发布的顺序保留。

只有功能接通、必要回归与正式包核验完成，并且所需实机检查有明确结论后，才将 Goal 标记完成。当前实现和候选包已接通，验收仍在进行；以下进展不等于最终完成。
