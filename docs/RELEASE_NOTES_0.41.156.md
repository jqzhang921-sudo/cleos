# 0.41.156：书名与全文线索分开

## 问题与行为

在「在线文库」搜索「窄门」时，旧版全文检索把正文中含有相关字符的判决书等文章列为候选，不能反映用户找同名读物的意图。搜索由文库 API 完成，不调用 TA 模型；更换模型不会改变候选准确性。

- 默认「按标题」先查询完整标题，使用来源 API 的标题规范化、中文简繁转换和重定向解析；核对标题转换链后才接受页面编号和固定修订。
- 只有完整标题查询成功但无有效页面时，才发起一次标题短语查询；本地再核对标题是否包含检索短语。不把正文里偶然提到关键词的文章作为默认补位。连接、HTTP、格式等错误不触发第二次查找。
- 常见书名号 / 外层引号会在查询前去掉。用户原输入仍作为草稿保留。标题短语的引号和反斜线转义，不将用户输入直接拼为搜索操作符；来源、响应和条数限制不放宽。
- 「全文线索」须手动选择并点击查找，结果明确标注为未确认目标作品的全文线索，可用于作者 / 关键词查询；不自动从标题模式切换过去。空标题结果明确说明未找到匹配标题，不声称这本书不存在或整库收录。
- 模式和查询草稿随页面重建保留，切换 TA 清空；改模式清空旧结果 / 错误但不自动请求。预览和保存流程沿用原有明确确认、来源、TA 隔离、进度与额度规则。
- 没有新权限、代理设置、依赖、数据表或后台任务；数据库 59、备份 24 不变。本版不修改用户 Clash Mi 配置，也不声称修复 VPN 或模型接口可达性。

## 网络说明

用户反馈 MiMo / DeepSeek 官方接口在当前代理路径报 connection closed，中转接口走代理可用。该现象不能推广为所有国内官方 API 不支持代理；域名、节点、DNS、HTTP 代理附加和分流路径均可能不同。已核对官方 API 文档中的常用实时推理域名 `api.deepseek.com`、`api.xiaomimimo.com`；可在用户的规则模式配置中分别选择直连，文库 `zh.wikisource.org` 走可用代理，实际以连接列表匹配结果和接口测试为准。
