## 工具诊断

- 「设置 → 关于 → 工具诊断」可复制最近记录或异常记录，也可标记刚才的问题和清除记录。没有报错但 TA 声称没有工具时，可手动标记。
- 自动启用结构诊断：模型名、请求编号、接口地址的单向指纹、发送工具数量/名称、MCP 发现数量及缓存成败、HTTP 错误类别、兼容重试、解析到的工具调用数量，以及 MCP 执行成败。
- 对明确的 dependentRequired 拒绝，将接口指出的工具编号映射为请求中的工具名，避免工具过多时名字预览截断了关键项。
- 不保存 Key、完整接口 URL、聊天正文、思考正文、工具参数/结果或原始响应。输入只允许固定的结构字段；记录不自动上传。
- 最近记录最多 128 KiB，异常现场最多 64 KiB，存于 noBackupFilesDir，不进入 Android 备份或 Cleos 数据备份。自动固定首次失败，保留同一请求后续的重试/结果；后来的正常请求不会覆盖它。清除后重新捕获，手动标记会替换原现场。
- 时间使用 UTC；每行带当时应用版本及会话编号，区分跨升级的记录。接口指纹不能还原真实 URL，复查时仍可由用户补充接口域名。
- 存储失败不向聊天抛异常；不会自动发送测试消息、调用额外工具或产生额外接口费用。
- 诊断记录是排查证据，不代表已经捕获或修复所有偶发问题。响应里有工具调用与工具真正成功执行是不同阶段；没有工具调用也不自动判定为故障。

## 旧闪退核对与玻璃坐标处理

- 用户确认华为、荣耀反馈来自 0.35.2，目前版本没有闪退反馈；没有这两类设备的具体堆栈，不能认定与 vivo 相同。
- vivo 文件标注 0.41.8、V2164A、Android 11/API 30；异常为 `layouts are not part of the same hierarchy`，发生在 UI 绘制堆栈。该版本匹配的 R8 映射未找到，未用当前映射错误反混淆，也未确认具体旧调用点。
- 液态玻璃已有跨弹窗布局根判断；背景合成仍有直接 localPositionOf 调用。本版将二者统一为 backdropOffset：同根使用局部坐标，跨根使用屏幕坐标；失效、非有限值或坐标异常时跳过这一帧背景采样，保留内容绘制。
- 不按手机品牌关掉玻璃效果，不更换绘制引擎，也不在全局吞掉任意绘制异常。此修改是对仍存在的具体坐标风险的补齐，不能宣称三个品牌实测通过。
- 另一个用户附件是旧版 FeedScreen 源码，不是崩溃日志；已对照查看，未覆盖当前朋友圈功能。
- 参考：Compose 坐标接口 https://developer.android.com/reference/kotlin/androidx/compose/ui/layout/LayoutCoordinates
