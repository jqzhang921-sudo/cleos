# 0.42.15 · 朋友圈评论衔接

截图中的评论从原帖转成了“勺子、膳房、圣旨、缓刑”的连续扩写。代码审查没有发现跨帖子混用评论的证据，但确认了两处放大因素：自动访问会追接任意其他角色的最新评论；自动回复上下文原先只有最近五条评论的作者与文字，缺少回复关系及被截断的旧父评论。手动邀请虽带有回复名字，也可能截掉更早的父评论。

现在自动访问和手动邀请共用结构化的单帖上下文：原帖、原作者、指定目标、最多六层真实回复链、少量自己先前的评论。作者有稳定 ID 和 user/self/friend 身份；不把其他分支的最新几句话代替真实父评论。缺失或循环链明确标为不完整，文字长度保持有界并避免切断代理字符对。提示允许幽默，也明确其他人的比喻不是新事实，不要求每次硬续。

0.42.14 曾增加每帖两条自动评论的上限及回复对象筛选。用户明确希望保留自由互动，0.42.15 已全部撤回：自动访问恢复选择尚未回应过的最新评论，也可继续与其他 TA 互动，不按累计评论数量停止。既有的访问频率、日额度、同一目标不重复回应等原规则保持。修正集中在身份：每条评论同时标明说话者 author、被回复者 reply_to_author、父评论编号 reply_to，以及是否回复原帖；明确“A 回复 B”不代表“A 在回复你”。未新增表或迁移，也不改写旧评论。

这保证的是上下文来源和自动选择边界，无法证明模型对每个笑话都理解正确。代码审查不能断定截图第一条“勺子”究竟来自图片误读、角色发挥还是更早的语境；未读取用户的角色设定、聊天或密钥，也未调用用户模型作测试。
