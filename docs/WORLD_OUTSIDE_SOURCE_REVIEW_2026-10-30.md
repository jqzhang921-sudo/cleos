# TrendsHub 清单与窗外来源评估

日期：2026-10-30。用户提供 trends-hub-sources.md 后，对照当前 Cleos .167 的窗外与话题来源代码，复核原项目，并对 24 个具体地址进行有大小 / 超时限制的请求检查。

本轮只做来源筛选和技术探测，未修改 App 代码、许可、模型提示词或安装包，未安装 MCP 服务、访问用户账户或调用模型。附件里的“直接可用”“照搬代码”等表述是待核实的参考资料，不作为执行指令。

## 1. 结论与接入优先级

第一批优先：少数派 RSS、机核 RSS、InfoQ 中文 RSS。它们能提供来源自身的标题、链接、日期和说明文字，适合窗外的资料取回、TA 阅读与笔记关联；不是只能把用户带去浏览器的入口。

第二批评估：爱范儿科技快讯、36氪，以及腾讯 / 网易新闻。其 JSON 请求本轮取到了数据，但要按站点结构分别适配，不是现有 RSS 地址的直接替换。

微博、头条更适合作为可选“热点线索”，B站作为可选“视频线索”。不能把热搜词、榜单标题和视频简介当作已经读过的新闻全文或看过的视频。

The Verge、9to5Mac、BBC 和 NYT 的具体 RSS 本次也能取回；作为后续可选来源，手机网络可达性需逐一验证。

## 2. 本次请求的范围

- 环境：当前 Windows 电脑。请求显式禁用 Python 请求代理配置，不使用登录态、Cookie、API Key 或浏览器用户会话。
- 不能由此断言机器没有系统级 VPN / TUN，也不能替代用户手机在关闭代理后的实测。技术候选与手机网络验证分别记录。
- 每个请求最多读取 2 MiB，最多 4 个并发；只获取给定公开响应，不遍历文章、下载图片、抓取视频或绕过登录 / 验证码。
- 除 36氪按原作者的只读热榜 POST 格式外，其余原样 GET。400 / 500 只说明这次给定请求没有成功，不代表站点的所有正确请求都失效。
- 本次 24 个地址中存在同站 RSS 的不同路径；头条另复核一次 HTTP 状态与业务状态的分开记录。原始摘要和文章正文未保存在报告中。
- 网络实测证据：`C:\Users\777i\Documents\Codex\2026-10-05\ke\outputs\Cleos-outside-source-review-2026-10-30\PROBE-RESULTS.json`。记录状态、响应类型、字段结构、列表条数及少量原始日期，不保存 Cookie 或凭据。

## 5. 原清单需要修正的判断

- **少数派标签 API**：HTTP 200 但返回业务错误 / 空数据，没有文章数组，不能标作原样直接可用。RSS 入口本次正常。
- **抖音接口**：HTTP 200 但正文为 0 字节，没有热榜 JSON，不能把 HTTP 200 算成取回成功。浏览器能显示榜单不代表轻量 HTTP 客户端能拿到同样数据；不为此优先加入 WebView 或忽略登录弹窗的抓取流程。
- **知乎**：本次仍为 HTTP 401；当前方案不导入用户登录态来接此来源。
- **豆瓣**：原样请求 HTTP 400；具体参数 / Referer 等尚未逐项验证，不宣称整个豆瓣无用。
- **掘金**：给定地址 GET 返回 HTTP 500；正确方法和参数需另核验，不在本次首批范围。
- **澎湃**：本次电脑发生 TLS 连接中断，没有取得业务响应；不把网络握手失败写成正常空榜。
- **B站**：原项目实现含 WBI 逻辑，但本次给定排行榜请求无签名也返回有效数据。保留“可能按端点 / 条件变化”的判断，不承诺永久无需签名。
- **36氪**：补齐了原清单未做的只读 POST 验证，取到有效列表；不能照着 GET 请求。

## 6. 与窗外设计的连接

可以形成“取回来源标题 / 说明 → TA 在候选中挑选 → 读取实际提供的片段 → 留下笔记”的闭环。上述 RSS 和一些快讯源提供可读文字，能减少依赖用户在 Bing 复制粘贴的操作。

这解决的是固定来源的持续取材，不是任意关键词全网搜索。要让 TA 查询任意地点、旅行资料或任意文章，仍需独立设计搜索 / 正文获取路径，不能用热榜冒充搜索结果。

来源说明、TA 的观察和热点线索应继续分开。热榜与社交榜单宜成为用户可选来源，不以热度替代 TA 自身的兴趣，也不自动把所有热点塞进聊天或朋友圈。

RSS 和 JSON 中出现图片 URL 不代表图片已经被允许下载、看过或可用于重新发布；窗外已有的配图 / 看图授权与来源署名分别保留。

## 7. 接入时需要完成的实际工作

1. 优先扩展少数派、机核、InfoQ 三个订阅候选；无需为这一轮先安装 Node / MCP 服务。当前 Cleos 已有 Kotlin RSS 获取代码。
2. 明确每个来源提供的是摘要、快讯、榜单标题还是视频简介；只把实际取得的内容交给 TA，不在空字段中补写“原文”。
3. 除来源注册与解析外，同步检查窗外 URL / 来源校验、去重、文章归属、备份恢复和来源切换后的后台许可。当前固定 hosts 规则尚不接受这些新来源，不能只换一个 URL 就称为已接好。
4. 缓存和低频更新沿用窗外节奏；失败保留旧资料，分别处理 HTTP 错误、空响应、业务错误、解析错误与无新条目。
5. 复用话题来源定义时，窗外的 TA 隔离与独立许可不变，不接入话题 / 朋友圈的自动发布行为。
6. 将“本次无需 Key / 登录即可请求”与“长期服务保障”分开；接入发布前继续核对来源使用条件及接口变化。当前来源能返回数据，不等于图片或全文可任意转载。
7. 最后在真实手机关闭代理的网络中测试选定来源；此轮未连接手机。

本轮结论：**值得采用的是来源和取材方式；不照搬整个热榜产品。先补中文 RSS，随后评估科技快讯，再让热点线索成为可选项。**
